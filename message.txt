Security audit: 7 passes, fix all 16 real findings

Ran the 7-pass security audit from StatesOfProjects/todo/CCChatShare-AUDIT-security.md
across all 13 sections. 36 findings: all 17 baseline security ids resolved with a
disposition, plus 19 new findings no tool reported. 16 disposed real, all fixed here.
Nothing rated P0 or P1.

Fixes:

- CSRF on POST /c/<slug>/unlock. A cross-site page could set a visitor's unlock
  cookie and burn their 5-per-5-minutes lockout budget for that share link. Added a
  stateless double-submit token: _render_unlock mints it into the form and a cc_csrf
  cookie (HttpOnly, SameSite=Strict, Secure, Path=/c/<slug>), and unlock_chat compares
  the pair with hmac.compare_digest before touching the db or the access code.
  deduct_when narrowed from != 302 to == 200 so a CSRF 400 or a 404 cannot spend a
  lockout slot. Standard library only, no new dependency.
- Strict-Transport-Security on every response. preload omitted deliberately: this host
  is one subdomain of a wider domain.
- CCCHATSHARE_HOST defaults to 127.0.0.1. Production is unaffected; the container
  entrypoint passes gunicorn its own --bind and the quadlet publishes loopback only.
- connect() chmods the sqlite file and its WAL/SHM siblings to 0600 and the parent dir
  to 0700, skipping a sticky directory so a /tmp path cannot lock other users out.
  A chmod failure warns and continues for read-only bind mounts.
- Markdown 3.6 -> 3.8.1 (PYSEC-2026-89, unhandled AssertionError on malformed
  HTML-like sequences) and bleach 6.1.0 -> 6.4.0 (GHSA-8rfp-98v4-mmr6, disallowed URI
  schemes above U+00A0). Both reachable on every GET /c/<slug>.
- render_markdown logs and degrades to html.escape'd text in a <pre> instead of 500ing
  a view over already-stored content. Escape is outside bleach, which may be the
  failing call.
- push_chat scans the title, not just the body. One cause behind three sinks: page
  heading, browser tab title, admin TUI table.
- The secrets scanner fails closed. _quoted_pass_hits raised no distinction between
  "clean" and "crashed", so a transient failure published an unredacted body. It now
  raises SecretsScanError and push_chat returns 503 with no row created.
- admin_tui action_toggle_revoke referenced an unassigned status_str, so every
  successful revoke raised NameError past the sqlite handler and crashed the TUI.
- README.md and SETUP.md stop documenting a /tmp database path.

Deferred, none disposed real, reasoning in the ledger: Flask and Werkzeug bumps
(advisories unreachable here, minor-bump regression risk), Containerfile digest
pinning, the local-only admin TUI identity check, and the in-container 0.0.0.0 bind.

Verified: 60 tests pass; 25/25 live smoke checks against local gunicorn and again
against the deployed VM; all 18 stored chats re-render clean under the new pins; the
admin TUI revoke toggle driven headlessly with textual run_test.
